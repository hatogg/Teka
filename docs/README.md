## Для розробників

«Тека» складається з нативної частини на Java, яка працює з файлами, виконує довгі завдання й роздає файли та мініатюри, та інтерфейсу на HTML/JavaScript у WebView без сторонніх бібліотек.

### Як рухаються дані

```
Дотик у інтерфейсі (www/js)
   ├─ швидке: Android.list / stat / mkdir / rename ──→ Fs ──→ JSON одразу
   ├─ запит:  Android.call(id, "archiveList", {...}) ──→ фоновий потік ──→ __teka.onResult(id, …)
   └─ довге:  Android.task(id, "copy", {...}) ──→ Ops.Job у пулі з 3 потоків
                 ├─ кожні 200 мс ──→ __teka.onTask(id, {state:"run", done, total, cur})
                 ├─ Archive / Convert / Apps роблять роботу, перевіряючи «скасувати»
                 └─ наприкінці: медіатека Android сканує змінені файли ──→ __teka.onTask(id, {state:"done", …})

<img src="/t?p=…">  <video src="/f?p=…">  ──→ shouldInterceptRequest ──→ Server ──→ Thumbs / файл з Range
```

### Принципи

1. **Довге — у фоні з прогресом і скасуванням.** Усе, що може тривати понад мить (копіювання, архіви, конвертація, хеші, пошук, аналіз), — завдання `Ops` з карткою прогресу; скасоване завдання прибирає недописаний файл.
2. **Оригінали не чіпаємо.** Конвертер і архіватор пишуть нові файли з унікальними назвами («(1)», «(2)»); перезапис — лише за явним вибором («Замінити»).
3. **Нічого не губиться відразу.** Видалення за замовчуванням — у кошик на тому ж сховищі (миттєве перейменування), з автоматичним очищенням через N днів.
4. **Перевірене — на JVM.** Архіватор, імена, кодування, HTTP-сервер для ПК, PDF із JPEG, BMP, WAV і перетворення PCM не залежать від Android і мають тести.

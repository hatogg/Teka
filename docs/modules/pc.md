# Доступ з ПК і застосунки

[← Документація](../README.md)

Файли: `PcServer.java` (чиста Java, тести в `test/PcServerTest.java`), `ServerService.java`, `Apps.java`.

## PcServer — сайт для браузера на комп’ютері

Невеликий HTTP/1.1-сервер на `ServerSocket` із пулом потоків. Сторінки — серверний HTML українською, без JavaScript, у кольорах «Теки».

| Адреса | Що робить |
|---|---|
| `POST /login` | Перевірка коду; кука `teka=<сесія>` (HttpOnly, SameSite=Strict) і перехід до сховищ |
| `/` | Список сховищ |
| `/b/<i>/<шлях>` | Папка (сортована, з розмірами й датами, формою вивантаження і новою папкою) або файл; `Range` для перемотування; `?dl=1` — завантажити |
| `/z/<i>/<шлях>` | Папка одним ZIP «на льоту» (стиснення 1, без тимчасових файлів) |
| `POST /u/<i>/<шлях>` | Вивантаження `multipart/form-data`, кілька файлів; розбір потоком з кільцевим буфером, тож розмір файлу не обмежений пам’яттю; збіги назв — «(1)» |
| `POST /m/<i>/<шлях>` | Нова папка |

**Безпека.** Без коректної сесії будь-яка адреса показує форму коду. Код — 6 цифр з `SecureRandom`, новий при кожному ввімкненні. Неправильний код — затримка 800 мс; після 5 невдач з однієї IP-адреси — блокування на 60 секунд. Кожен шлях перевіряється `Names.inside` (канонічні шляхи), тож `..%2F..%2Fetc` повертає 403. Сервер слухає лише, поки ввімкнено доступ.

`test/PcServerTest.java`: форма входу, неправильний і правильний код, кука, список сховищ і папки, файл цілком, `Range` (`1000-1999` і `-100`), вивантаження двох файлів (зокрема бінарного з `\r\n--` усередині), нова папка, ZIP папки (вміст і дані), вихід за межі кореня, неіснуюче сховище.

## ServerService

Служба переднього плану (`specialUse` на Android 14) зі сповіщенням: адреса, код і кнопка «Вимкнути».

- Корені — усі змонтовані сховища; порт — з налаштувань (типово 8080), а якщо зайнятий — будь-який вільний.
- IP-адреса — перший IPv4 інтерфейс у порядку: Wi-Fi (`wlan*`), точка доступу (`ap*`, `swlan*`), Ethernet/USB, інші; мобільні інтерфейси — лише якщо адреса локальна.
- Поки працює — `PARTIAL_WAKE_LOCK` (до 4 годин) і `WifiLock` високої продуктивності, щоб передача не переривалася при вимкненому екрані.
- Стан і події («Отримано з комп’ютера: 3 файли…») передаються сторінці через `__teka.onPc`.

## Apps

- **Список** — `getInstalledPackages`: назва, версія, системний/оновлений, чи має значок запуску, розмір APK з усіма частинами (`splitSourceDirs`), дати встановлення й оновлення, цільовий SDK. Службові системні пакети без значка не показуються.
- **Відомості про APK** — `getPackageArchiveInfo` з дозволами; назва й значок — після підстановки `sourceDir`; порівняння з установленою версією (`new`, `newer`, `older`, `same`). Для наборів APKS/XAPK/APKM показуються відомості `base.apk` і кількість частин.
- **Резервна копія** — `Download/Тека/APK/<назва>_<версія>.apk`; для застосунків з частинами — `.apks` (ZIP з `base.apk` і `split_*.apk`, без стиснення).
- **Встановлення наборів** — `PackageInstaller` сесія `MODE_FULL_INSTALL`: усі `.apk` з архіву записуються в сесію з прогресом, `commit` з `PendingIntent` (`FLAG_MUTABLE` на Android 12+). `InstallReceiver` показує системне підтвердження (`STATUS_PENDING_USER_ACTION`) і перекладає підсумок («Встановлено», «Конфлікт підпису», «Недостатньо місця»…).
- Звичайний APK встановлюється системним інсталятором через `FilesProvider`; перед цим перевіряється `canRequestPackageInstalls()` і, якщо треба, відкривається відповідний екран налаштувань.
